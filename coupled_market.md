# coupled_market.py — симулятор пары связанных классических бирж

## Назначение

Модуль симулирует две классические биржи (дискретные по времени книги заявок),
на которых торгуется один и тот же актив. Цены бирж похожи, но не одинаковы —
как цена биткойна на разных криптобиржах: разница между ними случайна,
но стационарна и притягивается к нулю.

Одна биржа настраивается «толстой» (ликвидной), вторая — «тонкой».
Повышенная волатильность и широкий спред тонкой биржи не задаются напрямую,
а возникают сами из мелкого стакана.

Агенты (в текущей версии) не торгуют на биржах, а хеджируются «на бумаге»:
запрашивают у биржи реалистичную оценку стоимости немедленного хеджа
по текущему стакану (`quote_hedge`). Архитектура позволяет позже включить
реальную торговлю без переделки (парный метод `execute`).

## Модель

### Время и такт (`CoupledMarket.step`)

Время дискретно. Один тик — строго следующая последовательность:

1. **Истечение** — на обеих биржах удаляются заявки старше `order_ttl` тиков
   (включая остатки частично исполненных; возраст считается от появления).
2. **Якорь** — пересчитывается по состоянию стаканов на конец прошлого тика.
3. **Фоновый поток** — обе биржи генерируют новые заявки вокруг одного
   и того же значения якоря (это и связывает цены).
4. **Аукционы** — на каждой бирже независимо проходит батч-аукцион.
5. **Статистика** — обновляется EWMA-волатильность.

### Якорь (`CoupledMarket._update_anchor`)

Якорь — цена, вокруг которой генерируется фоновый поток на обеих биржах:

```
взвешенный_мид = (mid_A * w_A + mid_B * w_B) / (w_A + w_B)
якорь          = EWMA(взвешенный_мид),  полураспад = anchor_ewma_half_life
```

Вес биржи `w` — суммарный лежащий объём в полосе `±depth_band` вокруг её мида.
Тонкая биржа получает малый вес и не может утащить якорь за собой:
ценообразование ведёт глубокая биржа (как в реальности).

Следствие конструкции: среднее двух цен блуждает случайно,
а разница цен возвращается к нулю (стационарный гэп).

### Фоновый поток (`Exchange.generate_background_orders`)

За тик приходит `N ~ Пуассон(arrival_rate)` заявок фиксированного размера
`order_size`. Для каждой заявки:

- сторона — монетка 50/50 (покупка/продажа);
- цена — **независимо** от стороны: `Normal(якорь, price_std)`, округляется
  к сетке `tick_size`, снизу ограничена одним тиком.

Независимость стороны и цены принципиальна: примерно половина покупок
оказывается выше текущих продаж и пересекает стакан — именно эти заявки
порождают сделки. Если задать `price_std` слишком маленьким относительно
типичного спреда, пересечений не будет и рынок замрёт.

### Аукцион (`Exchange.run_auction`)

Батч-аукцион с единой ценой: все сделки тика проходят по одной цене `p*`.

- Кандидаты на `p*` — ценовые уровни существующих заявок.
- `p*` максимизирует исполняемый объём `min(спрос(p), предложение(p))`,
  где спрос(p) — объём покупок с ценой ≥ p, предложение(p) — продаж с ценой ≤ p.
- Тай-брейк при равном объёме: цена, ближайшая к последней цене аукциона;
  при равном расстоянии — меньшая.
- Исполнение: уровни лучше `p*` — полностью, с приоритетом по цене;
  на маржинальном уровне (обычно ровно `p*`) — **pro-rata**, поэтому порядок
  прихода заявок ни на что не влияет.
- Нет пересечения — нет сделок: `last_price` не меняется, новые заявки
  ложатся в стакан.

Единая цена — ключевое свойство для мультиагентной симуляции: агентов можно
опрашивать в любом порядке, преимущества очерёдности не существует.

### Спорные случаи

Единое правило — «последняя цена»:

- пустая сторона стакана → `mid = last_price`;
- нет сделок в тике → `last_price` прежний;
- нулевая суммарная глубина у мидов → равные веса бирж в якоре.

### Метрики (`Exchange`, `get_state`)

| Метрика | Определение |
|---|---|
| `last_price` | цена последнего аукциона `p*` |
| `last_trade_volume` | объём последнего аукциона |
| `best_bid` / `best_ask` | лучшие цены покупки/продажи (`None`, если сторона пуста) |
| `spread` | `best_ask − best_bid` |
| `mid` | середина спреда (спорный случай → `last_price`) |
| `volatility` | за тик: `sqrt(EWMA(лог-прирост мида²))`, полураспад `ewma_half_life` |
| `depth` | объём по ценовым уровням, обе стороны от лучшего уровня вглубь |

### Оценка хеджа (`quote` / `quote_hedge`)

`quote_hedge(биржа, side, size)` — стоимость немедленного исполнения объёма
`size` по текущему остаточному стакану: проход по противоположной стороне
от лучшей цены вглубь. Если видимой глубины не хватает, исполняется часть:

```python
{"filled": 23.0, "total_cost": 2311.7, "avg_price": 100.51}
```

- `filled` — сколько удалось бы исполнить (≤ `size`);
- `total_cost` — стоимость исполненной части;
- `avg_price` — её средняя цена (`None`, если стакан пуст).

Стоимость ликвидности здесь настоящая: полспреда плюс проход по глубине,
на тонкой бирже дороже. Оценка не учитывает одновременные хеджи других
агентов и изменение стакана к следующему аукциону.

`execute(side, size)` — парный метод для реальной торговли; в v1 намеренно
`NotImplementedError`. Переход к v2 = реализовать его и заменить вызов.

## Параметры

Каждая биржа (`ExchangeConfig`):

| Параметр | Смысл | На что влияет |
|---|---|---|
| `name` | имя биржи | ключ во внешнем интерфейсе |
| `arrival_rate` | заявок за тик (Пуассон) | главный регулятор толщины |
| `order_size` | размер заявки (фикс.) | толщина |
| `order_ttl` | время жизни заявки, тиков | глубина стакана |
| `price_std` | std смещения цены от якоря | ширина стакана, доля пересечений |
| `ewma_half_life` | полураспад EWMA волатильности | сглаживание метрики |

Стационарная глубина стороны стакана ≈ `arrival_rate × order_size × order_ttl / 2`
— удобная формула для калибровки отношения толщин двух бирж.

Рынок (`CoupledMarket`):

| Параметр | Смысл |
|---|---|
| `tick_size` | шаг ценовой сетки (общий) |
| `initial_price` | стартовая цена: якорь, `last_price`, мид при t=0 |
| `anchor_ewma_half_life` | полураспад EWMA якоря |
| `depth_band` | полоса ±band вокруг мида для весов якоря |

Рекомендация: числовые значения полураспадов брать равными `order_ttl`.

## Использование

```python
from coupled_market import CoupledMarket, ExchangeConfig

config_a = ExchangeConfig(name="A", arrival_rate=40.0, order_size=1.0,
                          order_ttl=20, price_std=0.5, ewma_half_life=20.0)
config_b = ExchangeConfig(name="B", arrival_rate=8.0, order_size=1.0,
                          order_ttl=20, price_std=0.5, ewma_half_life=20.0)

market = CoupledMarket(config_a, config_b, tick_size=0.01,
                       initial_price=100.0, anchor_ewma_half_life=20.0,
                       depth_band=0.5)

market.warmup(300)                 # стаканы стартуют пустыми — прогреваем

for t in range(1000):
    market.step()                  # тик фонового рынка
    state = market.get_state()     # метрики обеих бирж
    q = market.quote_hedge("A", "sell", 25.0)   # оценка хеджа агента
```

## Известные ограничения (v1)

- **Хедж «на бумаге»**: агенты не оставляют следа в стакане — нет импакта
  и нет конкуренции за ликвидность. При массовом одностороннем хедже
  оценка стоимости систематически занижена.
- **Потиковые приросты цен бирж почти не коррелированы**: связь проявляется
  как возврат разницы цен к нулю, а не как мгновенное сонаправленное
  движение. Если нужна корреляция и на тиках — добавить разделение одной
  заявки между биржами в `generate_background_orders`.
- Общий генератор случайных чисел на обе биржи; воспроизводимость прогонов
  не предусмотрена.
